# MMA3001-project

**Reconstructing missing indoor CO₂ readings from a building sensor log**
MMA3001 Numerical Methods and Machine Learning individual project (Dataset 2: Monash Smart Infrastructure occupancy and environmental data).

## Research question

> How does the accuracy of reconstructing missing indoor CO₂ measurements degrade as gap duration increases, and how do linear interpolation and cubic-spline interpolation compare with a simple forward-fill baseline?

**Engineering context.** Building management and HVAC systems use indoor CO₂ as a proxy for ventilation adequacy and occupancy. Sensor logs contain dropouts, and analyses such as ventilation audits and energy/comfort reports need complete series. This project measures how well simple numerical methods can fill those gaps **retrospectively**, i.e. after the fact, using readings on both sides of the gap. It is **not** a real-time predictor.

**Data used.** One environmental sensor, `6012002000869` (Building 60, room G.38, "Compactus_upper", label EMS107 in `Sensor ID and Locations.xlsx`). The 29,341 raw rows contain 13,800 genuine CO₂ readings (29 Feb – 13 Jun 2024, about every 10 minutes); the rest are stale repeats of the last packet received. The other four sensors in the file contain no usable live data, and the occupancy file is not used (see [docs/report_draft.md](docs/report_draft.md)).

## Headline result (test period 14 May – 13 Jun 2024)

| Gap duration | Forward-fill MAE | Linear MAE | Cubic-spline MAE |
|---|---|---|---|
| 10 min | 9.2 ppm | **7.8 ppm** | 9.0 ppm |
| 1 h | 10.9 ppm | **8.2 ppm** | 13.0 ppm |
| 6 h | 17.8 ppm | **12.7 ppm** | 47.8 ppm |

Linear interpolation was the most accurate method at every gap duration tested. In a paired day-block bootstrap on the same test gaps, linear's advantage over both forward-fill and the spline is statistically clear at every duration: all 10 intervals for the MAE difference exclude zero, including after a Bonferroni adjustment (`results/co2_paired_bootstrap.csv`). In practical terms the advantage is small for 10-minute gaps (about 1.2–1.4 ppm) and large for long ones (35 ppm over the spline at 6 h). The cubic spline overshoots between noisy boundary readings and becomes the worst method from 30 minutes upward. Full tables with confidence intervals, bias, overshoot and runtimes are in `results/co2_test_metrics.csv`; the figures are in `results/figures/`.

## Reproducing the results

Run from the repository root with the virtual environment active. `PYTHONPATH=src` lets Python find the package without installing it (PowerShell: `$env:PYTHONPATH="src"`).

```bash
export PYTHONPATH=src
python -m gap_reconstruction.extract                          # -> data/processed/ (~5 s)
python -m gap_reconstruction.experiment                       # CO2, primary  (~30 s)
python -m gap_reconstruction.experiment --variable temperature   # supplementary (~30 s)
python -m pytest -v --junitxml=results/test-report.xml        # tests + XML report
python -m pdoc --docformat numpy -o docs/api gap_reconstruction  # HTML docs
```

Random gap placement uses fixed seeds, so rerunning reproduces every metric exactly. Runtimes vary with machine load.

## Method summary

1. **Extraction.** A reading counts as genuine only if its own measurement timestamp (inside the JSON) has not been seen before. 15,541 stale repeats are dropped; there were no conflicting duplicates and no invalid CO₂ values.
2. **Chronological split.** The first 70 % of readings (29 Feb – 13 May) form the development period and the last 30 % (14 May – 13 Jun) the test period.
3. **Artificial gaps.** Up to 200 non-overlapping gaps per nominal duration (10, 30, 60, 180, 360 min) are placed at random with a fixed seed. Three quantities are kept distinct:
   - **Nominal duration D** is a time window starting at a genuine reading; every reading in `[t_s, t_s + D − 5 min)` is hidden.
   - **Hidden readings** would be D/10 min under perfectly regular sampling. This sensor already misses about one reading in ten, so long windows usually hide fewer: in the test period, 3-hour gaps hid 16–17 readings (not 18) and 6-hour gaps hid 32–34 (not 36).
   - **Boundary interval** is the time between the known readings either side. It is about D + 10 min, plus about 10 min for each native missing reading bordering the gap. Test-period 10-minute gaps hid one reading, with boundary readings 20 min apart (173 gaps) or 30 min apart (27 gaps).

   All methods use identical gaps. Full distributions are in `results/co2_gap_definition_stats.csv`.
4. **Methods.** Forward-fill (causal baseline), linear interpolation, and a not-a-knot cubic spline (both retrospective). Every method receives the same known readings on each side of a gap, and a code assertion checks that no hidden reading reaches a method.
5. **Tuning and testing.** The spline context size (2–32 known readings each side) was chosen on the development period only. Every context was scored on the same 200 development gaps per duration (identical gap-set hashes are recorded in the tuning CSV). Context 2 had the lowest mean spline MAE (21.8 ppm vs 28.0–28.9 ppm). The test period was then evaluated with that setting. `python -m gap_reconstruction.experiment --tuning-only` re-runs only the tuning and gap statistics, without scoring the test period.
6. **Metrics.** MAE, RMSE and bias (ppm), with descriptive 95 % bootstrap intervals over gaps; midpoint error; overshoot; runtime per gap; cProfile output.
7. **Paired comparison.** MAE(forward-fill) − MAE(linear) and MAE(spline) − MAE(linear) on the same test gaps, with a paired bootstrap that resamples whole local days. Each replicate keeps every gap from each drawn day and scores all methods on that same set. 95 % and Bonferroni-adjusted (99.5 %) intervals are reported, with 3-day blocks as a robustness check. `python -m gap_reconstruction.experiment --paired-only` re-runs only this step on the existing test gaps.

## Tests

`python -m pytest -v` runs 98 tests on synthetic data and small fixtures in the real CSV format. They cover:
- JSON parsing and every rejection reason;
- removal of stale readings and handling of conflicting duplicates;
- conversion of timestamps to UTC;
- cadence and native-gap detection;
- exactness checks: linear interpolation reproduces lines and the not-a-knot spline reproduces cubics;
- convergence-order checks: linear error falls as O(h²) and spline error as O(h⁴);
- input validation;
- the leakage guard;
- gap placement rules;
- metric calculations;
- the paired day-block bootstrap: pairing, whole-block resampling, reproducibility, interval ordering and agreement with the main evaluation.

The latest results are in `results/test-report.txt` and `results/test-report.xml`.
